PROBLEM
-------
EB 89 (Бул. АСНОМ Бр.134, Аеродром) always shows "Се наоѓа во близина на 
Златна вилушка" in the property card. The real nearest landmark is 
"Парк Авионче" at 174m (a permanent park). "Златна вилушка" is a

The bug persists across TUI and PM2 server restarts.

RESOLUTION LAYERS (src/geo/landmarks.ts resolve() function)
-------------------------------------------------------------
0. Feed landmarks (Supabase) — EB 89 has none → SKIP
2. DB cache (SQLite landmarks table) — this is where "Златна вилушка" 
   keeps getting written and served from
3. Google Maps — no API key → SKIP
4. Details extraction — no match in property text → SKIP
5. Offline map (local OSM POIs, zero network) — WORKS CORRECTLY:
   - Geocodes "Бул. АСНОМ Бр.134" → (41.987890, 21.476493)
   - Finds Парк Авионче at 174m (park, score=209 with permanence)
   - BUT: the result is never cached because something fails first
6. OSM network (Nominatim) — returns "Златна вилушка" (WRONG, ~1km away)
   and writes it to the DB cache
7. Deterministic table — "Автобуската станица на Аеродром" (last resort)

FOR COMPARISON: EB 90 (Локов 5, Кисела Вода) works correctly:
- Offline map finds "Дом за слепи" at 164m → cached → served correctly
- Never hits the OSM layer

FIX #1: Missing fs import (src/geo/landmarks.ts line 26)
---------------------------------------------------------
ADDED: import fs from 'fs';

PROBLEM: The file used fs.appendFileSync() for debug logging in every 
resolution layer (lines 350, 371, 383, 396, 425, 429, 437, 469) but 
NEVER imported fs at module level. Every time a layer succeeded and 
tried to write the debug log, it threw ReferenceError: fs is not defined.
The catch block caught it, the layer's result was lost, and the function 
fell through to the next layer (OSM).

REMOVED: All `const fs = require('fs')` inside catch blocks (ESM incompatible)

FIX #2: OSM results polluting the DB cache (src/geo/landmarks.ts)
------------------------------------------------------------------
PROBLEM: The OSM layer (Nominatim) returns wrong/unreliable landmarks 
and writes them to the DB cache. Once cached, the DB cache serves them 
on every subsequent call (layers 3-7 never execute). The staleness check 
only invalidates "table" source, not "osm" source.

ATTEMPTED FIX: Added staleness check for OSM-sourced cache entries
IF the cached source is 'osm' AND the offline map is available,
re-resolve via offline map instead of serving the stale OSM result.

FIX #3: Permanence multiplier (src/geo/offlineMap.ts)
------------------------------------------------------
ADDED a PERMANENCE table and multiplied it into the scoring formula:

OLD formula: score = distance_m * (1 + priority/10)
NEW formula: score = distance_m * (1 + priority/10) * permanence

Permanent landmarks (parks, churches, schools): permanence = 0.55
Semi-permanent (hotels, malls, banks): permanence = 0.75
Temporary (shops, cafes, restaurants): permanence = 1.0

RESULT: Парк Авионче at 174m (score=209) beats Alka-U B at 117m (score=293)

FIX #4: Google Maps links for all nearby landmarks (src/handlers/inbound.ts)
----------------------------------------------------------------------------
CHANGED: Google Maps link now shows on ALL "каде?" asks (was 2nd+ only)
BEFORE: idx > 0 && coords
AFTER:  coords (always show link)

export class LandmarkStore {
  constructor(private db: Db) {}

  get(addressKey: string): { landmark: string; type: string; mapsUrl: string | null; source: string } | undefined {
    return this.db.db.prepare(
      `SELECT landmark, type, maps_url as mapsUrl, source FROM landmarks WHERE address_key = ?`
    ).get(addressKey) as any;
  }

  put(addressKey: string, l: { landmark: string; type: string; mapsUrl?: string; source: string }): void {
    this.db.db.prepare(
      `INSERT OR REPLACE INTO landmarks (address_key, landmark, type, maps_url, source, resolved_at)
       VALUES (?, ?, ?, ?, ?, ?)`
    ).run(addressKey, l.landmark, l.type, l.mapsUrl ?? null, l.source, Date.now());
  }

  getNearby(addressKey: string): Array<{ landmark: string; lat: number; lon: number }> | undefined {
    const row = this.db.db.prepare(
      `SELECT nearby FROM landmarks WHERE address_key = ? AND nearby IS NOT NULL`
    ).get(addressKey) as { nearby: string } | undefined;
    if (!row) return undefined;
    try { return JSON.parse(row.nearby); } catch { return undefined; }
  }

  putNearby(addressKey: string, nearby: Array<{ landmark: string; lat: number; lon: number }>): void {
    if (nearby.length === 0) return;
    // UPDATE only — the row must already exist from put(); never create a
    // row with only nearby (no landmark) to avoid partial entries.
    this.db.db.prepare(
      `UPDATE landmarks SET nearby = ? WHERE address_key = ?`
    ).run(JSON.stringify(nearby), addressKey);
  }
}

/** Canonical cache key — a property is identified by location + street, so a

  return `${p.location ?? ''} | ${p.address ?? ''}`.toLowerCase().replace(/\s+/g, ' ');
