# rsync-exclude.txt — the code-down / state-stays policy (one list, both directions).
#
# DOWN (deploy-atoms.sh): everything NOT listed here is pushed from the
# workstation to each atom with --delete, so the atom's code tree is an exact
# mirror of the workstation. Anything listed here is invisible to rsync: the
# atom's own copy survives untouched.
#
# UP (collect-atoms.sh): these same paths are the per-atom state we PULL back
# (into data/atoms/<atomId>/), review, and promote into the repo corpus by hand.
# Atoms never push; the workstation is the only git writer.
#
# Rule of thumb: if the atom LEARNED it or RUNS on it (databases, secrets,
# logs), it is listed here. If the WORKSTATION authors it (code, corpora,
# config templates), it is not.

# ── Live databases (the atom's own truth — never overwritten, never deleted) ──
data/*.db
# Any suffixed db file: .pre-*, .october, .bak.<stamp>, -shm/-wal style snapshots.
# The atom must NEVER receive a map copy — LINA reads skopje-pois.db from the
# maps-realestate project. These repair snapshots live in the workstation's data/
# and were silently shipped (46 MB) because `data/*.db` alone does not match
# `skopje-pois.db.pre-dedupe-*`.
data/*.db.*
data/*.db-shm
data/*.db-wal
data/*.db-journal
data/*.db.bak-*

# ── Per-atom learned state (self-enrichment products; collected, not pushed) ──
data/enrichment-log.json
data/address-overrides.json
data/feed-corrections.md
data/atoms/
data/capture/

# ── Per-atom secrets and logs ──
.lina/
logs/
*.log
nohup.out

# ── The atom's git object store is STATE, not code ──
# Without this, the push mirrors the workstation's .git with --delete: the atom
# lost the objects of its OWN commits (checked 2026-10-11 — atom01's HEAD
# 525bbd8 and d328d27 exist on no other machine), leaving a repo whose branch
# points at missing objects. Atoms never push, so their git is documentation
# only — but it must not be destroyed by a code deploy.
.git/

# ── The geo engine is NOT ours: src/geo is a machine-local symlink ──
# maps-realestate owns the geo engine (single source). src/geo here is a link
# created by scripts/link-geo.js; its target differs per machine, so rsync must
# never carry it — deploy-atoms.sh recreates it on the target instead.
src/geo

# ── Environment / local hacks (never in git either) ──
.env
GOOGLEMAPS_API_KEY.txt
session-*.md
tmp/
node_modules/
# dist/ is BUILT on the workstation (deploy-atoms.sh runs `npm run build`
# before the push) and MUST reach the atoms — excluding it here left every
# atom running the image's Sep-15 dist while the workstation source moved on
# (deploy reported OK, runtime never changed). The fleet contract comment in
# deploy-atoms.sh says exactly this: "ONLY code + dist/ are pushed".
# dist/
.tap/
supabase/.temp/
